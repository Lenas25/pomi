# Pomi — project notes for Claude Code

Open-source, local-first Android app (gym + healthy habits). Spec: `PLAN.md`. Design: `design/` (`HANDOFF.md`, `BRAND.md`, `ASSETS.md`, `tokens.json`).
Work by milestones (PLAN §18): tests green, one Conventional Commit per milestone, short summary.

## Language contract

- Code, identifiers, comments, commit messages, this file: **English**.
- User-facing strings live ONLY in `src/i18n` (`es` default, `en`). Route file names follow PLAN §5 (Spanish): `hoy`, `gym`, `habitos`, `progreso`, `ajustes`.
- No written content in code: exercises, habits and check-in texts come from `templates/` and i18n.
- Commits: Conventional Commits, no `Co-Authored-By` or AI attribution (user rule).

Tests: jest-expo + @testing-library/react-native 14 (uses `test-renderer`, not `react-test-renderer`). Lint: ESLint 9 flat config (`eslint-config-expo`) + Prettier.
Not yet installed (later milestones): Health Connect plugin (M5), expo-task-manager, expo-background-task, expo-sharing/print/file-system/document-picker, camera/image-picker, chart lib.
Development build only (no Expo Go). `android/` and `ios/` are generated by prebuild and git-ignored.

## Technical decisions

### Design / UI

- **Theme: light / dark / system only.** No "rosa/morado" accent theme exists (PLAN §13 / `templates/settings.json` `accent` are superseded). Setting value: `'system' | 'light' | 'dark'`, default `system`; held in `useThemeModeStore`, persisted in settings key `themeMode` (hydrated at startup by `useDatabaseReady`).
- **`design/tokens.json` is the single source of truth.** The only theme module is `src/ui/theme` (import it from there; `design/theme.ts` was removed). Components use ONLY theme tokens (no literal colors, sizes or font names). M0 added tokens `control` (button heights 48/56), `layout.maxContentWidth` (560), `stroke`, `opacity` (disabled/pressed) `motion.pressScale`, `color.transparent`, `layout.tabBarHeight` (scaled by the system font scale in the tab layout) and `icon.size`. `textStyle` throws in `__DEV__` when a font weight is not loaded.
- **i18n is reactive:** components call `useT()` (bound to `useLocaleStore`); the plain `t` is for non-React code. The language preference (`system | es | en`) is persisted in settings key `language` (`system` = key removed) and hydrated by `useDatabaseReady`.
- Interactive `Card` requires `accessibilityLabel` (discriminated props). `MascotPose` is derived from `mascotImages`. `noUncheckedIndexedAccess` is on.
- **Fonts:** heading = Fredoka (600, 700); body = Nunito Sans (400, 600, 700); numeric (timer/metric) = Nunito 900 with tabular digits. Loaded in `app/_layout.tsx` before hiding the splash.
- Icons: Phosphor, `IconContext` default weight `bold`, size 24, color from theme (`IconProvider`). Template `icon` emojis map to Phosphor icon names; emoji is allowed only in notification text (max one).
- Mascot is decorative (`accessible={false}` + `importantForAccessibility="no-hide-descendants"`); `MascotBubble` is a polite live region and warns in dev above 40 chars. Reduce-motion (`useReducedMotion`) disables scale/translate, keeps a 120 ms fade, and press feedback keeps the opacity dim.
- Android package is a placeholder `pe.nakea.pomi` (BRAND says the name/package is still to be decided). `minSdkVersion` 26 (Health Connect).
- Charts library: decide in v2.

### Templates and data

- Template schema extends PLAN §6.2 with `muscles`, `rules`, `onlyIf`, `glassMl`, `source` (implemented in `src/templates/schema.ts`).
- **Template `icon` = Phosphor component name** (PascalCase, e.g. `Barbell`, `Drop`); emoji is rejected by the importer. Schemas are strict: unknown keys are errors (`unknownKey`, with the full path) except keys starting with `_` (e.g. `_note`), which the importer strips before validating.
- **Importer** `importTemplate(json)` / `importTemplateFromText(text)` returns `{ok, template}` or `{ok:false, errors[]}`; each error is `{code, path, params, line?}`. Show them with `describeImportError(error, t)` (messages live in `importErrors.*` i18n, es + en). Bundles (`kind: modules`) are split into module rows via `toModuleTemplates`; `kind: settings` is applied to settings/profile, never stored as a module.
- **Bundled defaults:** `loadDefaultTemplates()` validates `templates/*.json`; `templates` repository `seedDefaults()` seeds the modules once (flag `templatesSeeded`). The settings template is only an author example and is not seeded.
- **Exercise history key = step id** (global across routines); today's routine supplies the rep range.
- **reps parser:** `"8–10"` → `[8,10]`; single number (`"8 por lado"`) → `[8,8]`; seconds ranges (`"30–45 s"`) are time, not reps; compound text (`"12–15 + 10 pulsos…"`) uses the first range; bodyweight (no `incrementKg`) only gets +1 rep.
- **Gym days source of truth = settings** (from onboarding), not `program.schedules`.
- `bed` is derived: `wake − sleepTargetH`.

### Formulas

- **Water:** 33 ml/kg + 500 ml per gym hour (1 h per session by default), rounded **UP** to 250 ml glasses.
- **Steps v1:** goal fixed after the baseline week (baseline + 1000, rounded to 500, cap 10000). Weekly auto-adjust only through suggestions (v2), never silently.

### Companion features (PLAN §14b)

- **v1:** evening "¿Te moviste hoy?" notification with actions (gym / walk / no) writing `activity_logs` even with the app closed ("Hoy no" is never a miss); sleep-cycle calculator (`wake − n×90 − 15`, n = 4..6).
- **v2:** sleep debt (7 days, daily surplus capped at 60 min, min 4 days), social jetlag (midsleep difference, 14 days), water curve by hour (suggestions only), "Tu ritmo" profile (min 21 days, prudent wording), Sunday "Carta de Pomi", configurable sedentary nudge from Health Connect hourly steps in a background task (approximate, ~15 min; Android may delay it).
- **v3:** optional on-device LLM ("Pomi conversa"): deterministic engines compute every number, the LLM only verbalizes via tool calls, strict healthy-life scope, no medical advice, template fallback.
- Every number comes from a pure engine in `src/domain`; text generation never computes.

### Timers and notifications

- Timers store an `endsAt` timestamp. 3-2-1 beeps only in foreground; the end alarm is a scheduled local notification, so it works with the screen off.
- The scheduler trims to **64 upcoming notifications on every platform** (not just iOS; Android OEM limits too).

## Gotchas learned in M0

- No `babel.config.js`: SDK 57 resolves `babel-preset-expo` internally; a manual config with that preset fails (`Cannot find module 'babel-preset-expo'`).
- Jest needs `jest.setup.js`: Reanimated/Worklets mocks, and `useReducedMotion` is not in Reanimated's official mock, so it is added there.
- RNTL 14 renders asynchronously: `await render(...)` and `await fireEvent.press(...)`.
- `expo install` pulls `react` 19.3 / `@types/react` 19.3; `react` is pinned to 19.2.3 (RN 0.86 renderer) and `@types/react` to `~19.2.4`.
- `typedRoutes` is intentionally off (typed hrefs need generated `.expo/types`; `tsc` must pass on a clean checkout).

## Database conventions (M1)

- Drizzle + expo-sqlite (`openDatabaseSync('pomi.db')`, `PRAGMA foreign_keys = ON`). Day keys are `yyyy-MM-dd` text; timestamps are integer epoch ms; JSON columns use `text({ mode: 'json' })`.
- Schema changes: edit `src/db/schema.ts`, run `npm run db:generate`, commit `drizzle/` + `src/db/migrations.generated.ts`. Migrations are bundled as strings by `scripts/build-migrations.js`, so there is NO `babel.config.js`, no `babel-plugin-inline-import` and no Metro `.sql` rule. Do not use the `drizzle/migrations.js` that drizzle-kit emits (the script deletes it).
- Migrations run under the splash: `app/_layout.tsx` waits for `useDatabaseReady()` (migrate, seed templates, hydrate theme) before rendering; on failure it shows a localized error screen.
- Repositories (`src/db/repositories/*`) are factories over an injectable `Db` (`BaseSQLiteDatabase<'sync' | 'async'>`). Always `await` queries; no transactions or driver-specific APIs. They hold no domain logic. App code uses the `repositories` singleton from `src/db`; never import `src/db/client` from domain code or tests.
- Settings are a typed k/v (`settingsSchemas` in `repositories/settings.ts`, zod-validated on read): `anchors`, `gymDays`, `themeMode`, `language`, `activeModules`, `checkinPrefs`, `templatesSeeded`. `templates.active` = module installed/enabled; `activeModules` = user feature toggles from onboarding.
- Repository tests run on Node's built-in `node:sqlite` through Drizzle's sqlite-proxy (`src/db/testing/createTestDb.ts`, applies the real migrations). No better-sqlite3. Requires Node >= 22.5.

## Domain conventions (M2)

- `src/domain/**` is pure TypeScript: no React, React Native, Expo, Drizzle or `src/db` imports (enforced by `src/domain/domain.test.ts`). `date-fns` and type-only imports from `src/templates/schema` are fine. Input in, value out; no clock access (callers pass the date).
- Time of day is `HH:mm` strings or minutes of the day (`time.ts`). Everything crossing midnight wraps; agenda minutes `>= 1440` mean "after midnight, end of today's timeline" (a bed time of 00:30 is 1470).
- Domain functions return i18n KEYS + params (`TargetMessage`), never text. Keys live in `src/i18n` (`gym.target.*`, `agenda.*`); tests assert every emitted key exists.
- **Water:** `waterGoal({weightKg, gymHours, glassMl})` -> `{rawMl, glasses, ml}`; rounds up (float noise guarded). **Steps:** baseline = mean of the last 7 days (needs >= 3, else the onboarding answer); `initialStepsGoal` = baseline + 1000 to nearest 500, capped; `proposeStepsAdjustment` is a pure PROPOSAL (raise at >= 5/7; lower after 2 consecutive weeks < 3 days, floor = baseline; the caller passes `daysMetPreviousWeek: undefined` after a goal change).
- **Sleep:** bedtime = wake − target; wake regularity = circular RANGE (max − min) of wake times over the last 7 morning check-ins (matches the ">60 min" rule); cycles calculator = wake − n×90 − 15 (n = 4..6).
- **reps parser:** returns `{kind:'reps', min, max, perSide}` or `{kind:'time', minSec, maxSec}` or `null`; first range wins in compound text.
- **Rotation:** routine with sets logged today > next after the last COMPLETED session (wraps) > first.
- **todayTarget:** history is per step id, most recent FIRST. Working weight = heaviest set. Case 1 needs every planned set at the top with RIR >= 1/unknown; no `incrementKg` -> +1 rep beyond the range. Case 2 adds +1 rep (capped at the top, floored at the min) to every set below the top. Stall = each of the last `stallSessions` sessions failed to beat its predecessor (needs `stallSessions + 1` sessions); deload weight rounds to 0.5 kg. RIR >= 3 on every set (all recorded) for 2 sessions -> "go heavier" suggestion.
- **buildAgenda(date, state):** gym comes from settings `gymDays`/anchors (never `program.schedules`); `bed` is derived; habits are filtered by `onlyIf` (`profile.*`), steps by `When`; a habit whose schedules do not apply today is dropped; all-day items (steps, unscheduled habits) sort last. Water goal uses 1 h of gym on gym days.
- `src/domain/testing/syntheticData.ts`: seeded 60-day generator (gym -> +35 min sleep, later weekends, afternoon water dip) for suggestion/insight/chart tests.
